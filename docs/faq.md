# FAQ

## 为什么只能导出 2400 条？

那是依赖 DLL 的工具的限制。本项目直接解密所有 `message_*.db` 分片并在 SQLite
里合并，不受这个上限影响。如果你仍然只看到 2400 条，说明用的不是本工具。

## 报错“数据库头无效，密钥可能不正确”

- 检查密钥是否是 64 位十六进制，没有空格/换行。
- 确认密钥属于当前账号；多账号时不要混用。
- 微信升级后密钥机制可能变化，先运行 `doctor` 看具体错误。

## 导出的消息比客户端少

- 检查 `message_*.db-wal` 是否非空；有 WAL 时最新消息可能还没 checkpoint。
  先退出微信再导出，或关注后续版本。
- 确认 `--since/--until/--limit` 没有过滤掉。
- 群聊里被撤回/删除的消息可能本来就不在库里。

## 图片全是 `[图片]`

- 图片 `.dat` 需要能找到文件，且有时需要单独的 image key。
- 先用 `--image-mode auto`（默认），它会尝试消息 XML 里的 `aeskey`；
  仍失败时用 `--image-key-file` 提供账号 image key。
- 部分 WXGF/WxAM 图片暂不支持，会降级占位。

## 群聊发送者显示 wxid

群昵称需要 `contact.db` 里有对应信息。工具会尽力解析备注/昵称，解析不到就显示
wxid，不会伪造名字。

## PDF 中文是方框/报错找不到字体

用 `--pdf-font` 指定一个中文 TTF/TTC，例如：

```bash
--pdf-font "C:\Windows\Fonts\msyh.ttc"
```

Linux CI 环境通常没有中文字体，测试会自动跳过 PDF。

## 会修改微信数据库吗？

不会。工具只读解密副本，原数据库和微信客户端都不被写入。

## 支持 macOS / Linux 吗？

核心解密和导出是跨平台的，但微信 4.x 的数据库主要来自 Windows 客户端。
其他平台没有经过验证，欢迎提交测试结果。
